# Oryn Protocol

Canonical JSON Schemas, golden fixtures, and TypeScript/Python bindings for the versioned Oryn Browser ↔ Oryn Engine contract.

## Develop

```bash
pnpm install
uv sync --project python --extra dev
pnpm validate
```

The root `schemas/` directory is canonical. The Python package copy is generated by `pnpm sync:schema` and verified by the shared fixture tests.

`schemas/task-contracts/registry.json` owns all existing task definitions and
`task-profile.schema.json` defines their effective backend profiles. The sync script
integrates them into Protocol v1 and the Python package. TypeScript and Python use
the same negotiation fixtures. `scripts/export-sdk-task-types.mjs <destination>`
generates the SDK's public profile/requirements types; SDK publication remains separate.

No package is published by repository scripts. Publication requires an explicit release decision.

Embedding adapters may explicitly declare `inputType` (`query` or `document`) and
`contextual`. With `contextual: true`, the ordered `texts` are chunks of one document
encoded together; output rows retain their input order. Queries cannot use contextual
chunk grouping. Without grouping, each text is independent. Models must advertise
these controls before callers send them. The registry's `declarationRequiredParameters`
keeps new controls out of ordinary profiles unless an adapter declares them; existing
embedding profiles continue to accept only their original controls. Older registries
reject profiles containing controls they do not recognize.


Model requests support source-checkpoint, preferred-variant and exact-artifact intent
with file-sensitive identities. Recommendation data remains separate from runtime
trust and public task contracts. See the [SDK API reference](../oryn-sdk/docs/api-reference.md).
